## Exact preparation contract and error timing

Keep the single public SDK `prepare_work_registration(initial, grant, input)` and
`register_work_item(prepared)` / portable `resolve` and `recover` family. Revise
their documented guarantee in place; no permanent parallel eager API is selected.
Engine `prepare_registration(repo, grant, basis, input)` may retain its signature:
`basis` must equal the grant's supplied original basis by pure equality; SDK passes
`grant.basis`. `repo` is consulted only for kind retained binding. This signature
does not establish that supplied project/root bytes describe the current repository.
`resolve_current_work_registration_terms` stays a live observation callers can
request independently, with no reservation or eventual-success promise.

Recommended deterministic binding sequence:

1. SDK validates complete supplied initial locator, then initial/check equality.
   Engine validates supplied grant/check/terms/fingerprint, then exact supplied
   basis equality (`work_basis_stale` remains the mismatch refusal).
2. Validate the closed registration input, supported absent-to-open effect,
   token/text/UTF-8 byte limits and supported composition/role. Derive item
   identity from exact project/key. For Kind, validate exact binding and same
   project before retained reads; resolve committed K1 with one `store::open`/
   `scan` and existing historical closure. No current operating guards or current
   grant selection are required for this read. Validate the work lock before
   returning; release root/lock and scan guards before returning preparation.
3. Build exact provenance (committed establishment receipt plus expansion),
   effective input and original request identity. Validate declared grant scope,
   exact actor/project/item/request/provenance/fingerprint and closed locator
   bytes/limits. Return sealed `PreparedWorkRegistrationV1` with its complete
   portable locator available through `locator()` before invocation.

For Explicit/RetainedExplicit, provenance is absent and this is wholly pure:
**zero work scans, store/root/native guards or live applicability observations**.
For Kind, **one existing full scan** is the structural target, conditional on
proving its exact committed binding evidence; no point-file shortcut is selected.
Grant currentness/activation is not necessary for deriving either original
locator. Candidate grant bytes can bind but cannot authorize invocation. Kind
shape alone cannot establish committed provenance. A valid K1 remains bindable
as retained truth after its establishment basis ceases to be current.

## Item seam comparison and recovery integration

Both wrappers acquire `OperatingGuard::acquire(..., false)` first: initialization,
promotion, registry, lifecycle and operating locks, then current check resolution,
authority tree and borrowed `WorkRegistrationCurrentV1`. The consuming callback
opens the work store/lock afterward. Both validate admission before consumption
and after successful consumption; errors short-circuit and RAII releases guards.
`capture_proof` and all callback validation use the same admission type.

Establishment additionally validates the guard before/after its bootstrap
callback, resolves current native basis twice and compares fingerprints before
retaining the tree. This is necessary when `store::establish` creates the sibling
partition. For Item the callback performs no establishment (`Operation::bootstrap`
is only Kind/Grant); current-wrapper tree capture occurs after the initial
current-check and before the same pre-consume validation. It has no sibling
creation to accommodate. The retained tree inventories ancestors/siblings,
including unselected entries, without recursively treating work-state writes as
native-authority mutations; see [durability](../../../../../crates/engine/src/repository_durability.rs),
`retain_selected_tree` 849–924.

Route **Item only**, including original Item recovery, through
`with_work_registration_current`. Leave Grant/Kind genuine bootstrap and Revoke
routing unchanged. Keep the common consuming body and final execute outcome
mapping, including `effects` tracking and `close_noncommit`. Item must retain the
pre-wrapper positive-owner check and refuse unestablished owner rather than create
it. No store-opening gap is added between held native admission and work lock.
I1 still completes and releases its work lock before acquiring native locks; do
not invert order by retaining I1 through native acquisition.

Removing the no-op bootstrap's pre-tree observation pair is a deliberate narrow
seam simplification, not proof that every transient failure would produce the
same first diagnostic. Before any Item effect, the current seam still re-resolves
the captured authority fingerprint and validates its retained tree/guard. Prove
equivalent current-authority refusal and physical detection at the retained
admission/capture/publication stages with targeted faults; retain a necessary
check if evidence shows a protection gap. Do not bypass a physical observation
to obtain a faster wrapper. All work inventory/manifest checks remain.

| Original retained state | Required preserved behavior |
| --- | --- |
| Exact committed closure/terminal, including lost reply or postterminal error | Replay original bytes/outcome before live permission; no new slot/effect. A postterminal failure is never asserted noncommit. |
| Positive complete inventory with no original | Resolve `Unaccepted`; recovery returns it and cannot start a request. |
| Accepted complete never-attempted original | Continue only with exact original usable grant/basis and kind; consume no new admission slot. Never substitute successor, overlapping grant or G for D. |
| Live original authority unavailable before supported terminal attempt | Existing `close_noncommit` proves complete original/prefix and writes/verifies positive noncommit only when neither staging nor attempted; keeps immutable request history. |
| Missing/partial/staged evidence or attempted without exact terminal | Preserve refusal/`Uncertain`, reservation and occupied slots. Early candidate/slot prefixes may remain unresolved indefinitely. Missing evidence is never absence, timeout cancellation or retry permission. |

The complete locator must be caller-retainable **before `reserve_intent`**, not
merely before terminal or in the final reply. Keep the existing save-locator/
invoke/resolve/recover pattern and response guidance. No new durable preparation
