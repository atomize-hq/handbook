## Why this increment and what it demonstrates

The real observer already exists. The initial consumer cannot currently obtain
usable owner-backed setup/Engine authority: public Charter dispatch injects an
unavailable authenticator, and `load_authority_snapshot` uses the private HCM-3.2
non-family authority-artifact/publication tuple. An instruction parser or profile
label would leave that obstruction intact. This packet must establish real native
Charter/posture and local operating authority, then exercise Engine's actual
admitted-envelope checks after restart.

Example, with illustrative paths only: the human approves P's exact Charter and
posture vector, defers the exact freshness admission scope, selects a supported
local advisory setup/operating rule and delegates local validation within the
identified input paths and owner-write reach. A typed SDK caller retains each
owner's locator, establishes those native outcomes, reopens P and resolves the
same committed Charter and instruction. Engine admits the local envelope and
allows the declared validation horizon and permitted owner-write path. A request
for a different root, wider path or validation horizon refuses. Revocation or
an invalidating Charter/instruction-head change stops fresh use, while exact
historical delivery preserves the prior setup outcome.

This proves supported initial setup and actual Engine admission/non-expansion.
It does not prove Evaluation Authorization for a formed Purpose, capability,
Contracts lifecycle/source authority, a Dock attempt, evidence or result truth.
Those responsibilities remain allocated to later packets in the slice.

## Native interface and persistence boundary

Use purpose-named typed Rust SDK methods for preparation, execution, exact
request recovery and current resolution. The SDK returns separate owner outcomes
and composes sequentially; it does not make setup one fictitious atomic transaction.
Native Engine services establish Charter/approval/promotion and operating terms;
Contracts supplies deferral and v3 current applicability. Native inputs are supplied
by the adaptive agent conversation, not generated recommendations in initialization.

The bounded new operating input binds: exact project registration/root identity;
committed Charter revision/posture and compatible definition closure; explicit
approval of those initial choices; actual actor/delegation claims and assurance
mode; allowed operation classes, local path/reach bounds and owner writes; reserved
decisions and any delegated resolution classes; exact initial instruction and
supported rule/version; request identity, current predecessor and invalidation/
revocation terms. Terms may permit classes of future bounded operations, without
preapproving every future payload hash. Each use binds its actual subject/reach.
Unknown fields, unsupported classes/modes, conflicting identities, excessive reach
and incomplete required inputs refuse. No absent-file, title or context inference.

Support only fresh initial local setup on a positively registered defer-first P
and exact replay/reopen of that setup in this packet. Existing ordinary roots or
already selected incompatible Charter/operating state refuse with the needed
boundary; no reset, migration or second bootstrap. Reuse deferral preparation and
initialization before ordinary Setup, preserve P's identity/history and original
locators. A complete existing v3 footprint is read through v3 even if D remains
current. Established G dependent qualification is not implemented by this packet;
recognize the exact current basis and refuse unsupported dependent use.

Establish immutable operating terms plus an exact current-head relation using
retained-root/durable owner primitives. Support an authorized revoke against the
exact current predecessor under the initially declared revocation terms; no new
authority or broad successor replacement is added. A replayed initial request
cannot reactivate revoked authority. Preparation has no effects; serialize a
complete recovery locator before effects. Owner outcomes distinguish validation,
accepted advisory permission, committed effects, refusal, noncommit and uncertainty.
If Charter commits but terms do not, report those exact outcomes and resume only
the unresolved original request. No fabricated rollback or reset.

Engine's new supported local admission must resolve native committed initial
authority and bind root/Charter/terms/rule/current heads, exact envelope candidate
and constraints. It must make the existing native envelope non-expansion checks
usable without rewriting v1 credential admissions or manufacturing their witnesses.
Engine retains current/historical validation of its own lineage. A sealed live
admission cannot be serialized into reusable permission. A serializable owner
locator/output is resolvable history, with fresh current checks before new use.
Same path/reference with changed content refuses; restart resolves retained truth
rather than relying on the in-memory Context Resolution cache.

The first release of this packet returns exact refusal and a bounded unresolved
request context: original operation/basis, missing condition, requested choice,
permitted resolver class under prior terms, and relevant exact source references.
It need not auto-route or accept a returned project-agent decision yet. Do not
hardcode “human required” for every escalation; distinguish reserved, delegated
but unimplemented delivery, and unresolved authority. Substrate's existing host
agent/configuration/dispatch facilities remain candidates for later delivery.

Preserve owner lock ordering and generation/root checks. Finish/release native
governance calls before invoking Charter/registry/Context Resolution; never call
them under governance locks. Current-head observations separated from use by an
unguarded gap cannot certify current authority: the Engine consuming boundary
must retain/revalidate its required exact guards or refuse. Concurrent revoke,
Charter replacement and root/identity substitution require discriminating tests.

## Work and acceptance

Implement only this connected initial-authority outcome, in dependency order:

1. Establish the additive owner contract and compatible local definition closure,
   preserving current verified paths. Add native exact initial advisory approval/
   promotion and retained operating terms/revocation against their true owners.
2. Compose fresh defer-first registration, native Charter/posture setup and terms
   through typed SDK, with per-owner locators and honest partial outcomes/recovery.
3. Integrate the local native Engine admission into actual envelope checks; prove
   use after reopen, exact in-bounds validation/path decisions and wider/stale
   refusal. Return the bounded unresolved request without claiming routing.

Acceptance requires all of the following:

- An ordinary typed SDK consumer outside the integration fixture can establish
  supplied approved initial inputs through native owners, reopen and resolve the
  same Charter/posture/D/terms. No hand-written private authority files, synthetic
  credential assertions or constructed dimensional-only admission can substitute.
- Actual Engine admission permits the selected local validation horizon and
  owner-write reach; wrong subject/root/constraint/profile/rule/Charter/terms or
  wider reach refuses. This is a native usable authorization outcome, not a label.
- Initial choices are separately attributable and honestly advisory. Missing
  required approval/terms refuses; the selected local route needs no authenticator.
  Existing credential-required requests still refuse missing authentication; no
  automatic mode downgrade, fabricated quorum/independence or role-based grant.
  Routine re-admission after restart needs current owner checks, not a repeated
  human decision solely for that operation.
- Replay/recovery preserves exact identity/history and never restores revoked
  current state. Interruption and concurrent setup/revoke/root change yield exact
  commit/refusal/uncertainty. Required state loss refuses, never reinitializes.
- Native compatible definitions and authored Charter lifecycle are actually usable
  together; old shipped exact closures/verified assurance and v1/v2/v3 governance
  contracts retain their meanings. No new generic authored family is introduced.
- Refusal context preserves a path for later authorized agent resolution, with
  truthful partial-delivery limits. No Contract/source/producer/evidence/truth,
  Work Progression, shipment, host enforcement or complete local-check claim.

Likely implementation ownership is Engine's Charter intake/approval/promotion,
definition/profile selection, Context Resolution and a focused local-authority
module; typed SDK composition and focused Engine/SDK tests. Contracts changes
are limited to genuinely necessary compilation or v3-consumer integration; its
governance transaction/contracts remain unchanged. Product files are not edited
