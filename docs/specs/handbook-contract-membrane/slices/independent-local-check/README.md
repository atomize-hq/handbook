## Complete outcome

For one actual local project, a skill-guided agent gathers the payload/schema
need and unresolved choices, proposes justified Charter/posture and operating
terms, and obtains initial human approval of those choices and governance or
deliberate scoped deferral. Native owners establish the supplied supported inputs.
Within that delegation, a typed Rust SDK consumer completes an offline JSON
payload check against an exact supported local Draft 2020-12 schema closure using
`handbook.dock.json-schema@1.0.0`. Contracts owns the admitted evidence and closed
result. A deliberately fresh repeat or permitted payload correction produces
new occurrence truth. An out-of-bounds request is refused with its exact reason
and, where resolution is possible, a bounded request for an authorized decision.

The question is “Does this exact captured payload conform to this exact schema
closure?” It is useful independently under positive scoped applicability and
does not become Draft solely because governance is deferred. A completed
nonconformant observation is a valid unfavorable result, with violations.
Invalid authority, applicability, capability or closure refuses formation/use;
it cannot be presented as that semantic failure.

Recommend one claim, one case, one native producer selection, complete direct
requirements, `Decision-seeking eligible` permitted use and `decision_seeking`
intent, with no metrics unless the real question needs them. These are proposed
product selections, not existing V1 fields or the user's runtime criteria.
The schema and complete evaluation definitions must be independently justified
from the need before inspecting outcomes. Test payloads and numerical policy
values do not choose actual bounds or fit criteria to a pass.

Initial choices still require human decisions. No new approval for a later
operation means prior terms already permit it, with native currentness, scope and
content checks. Delivery, decision authority, assurance and composition remain
separate; a configured role or transport never grants permission.

## Owner and host boundaries

Engine owns Charter/posture, operating definitions/envelopes, exact request
non-expansion and authorization issuance/currentness. Contracts owns intrinsic
definition conformance, applicable qualification, complete direct requirements,
Evaluation Coordination, evidence admission/closure and semantic truth. Dock
owns exact package/request/execution/observation provenance. SDK composes these
owners and exposes typed consumer results; it cannot select a missing rule,
approve a scope expansion, or reconstruct Engine decisions. No owner depends
back on SDK or Substrate.

The minimum host interface is caller-carried typed requests/results: exact
project/root, current basis, intended operation and reach, original instruction
and assurance provenance, and exact refusal/decision-request context. A later
resolution submission binds the original unresolved request, proposed choice,
decision source and prior delegated authority; the responsible owner accepts,
denies or requires clarification. Delivery/timeout cannot grant permission.
Initial decisions remain human decisions. A configured role, more context or a
host session token is insufficient native authority. A project-level agent can
resolve only choices the prior terms actually delegate; human escalation is for
reserved decisions, unresolved material ambiguity or missing authority with no
authorized resolution.

Packet 1 returns refusal and unresolved context only. It does not implement
routed agent escalation or claim that a project agent has resolved anything.
The full slice's minimal request/decision submission can operate with a caller
or manually delivered project-agent response. Automatic discovery/delivery,
general agent profiles, profile-specific context assembly and a complete
Substrate adoption adapter remain tracked in the
[coverage carry-forward](../../coverage-and-landing-map.md#local-check-planning-and-host-integration-carry-forward)
and [Phase 6](../../phase-and-slice-map.md#phase-6--consumer-adoption).

## Complete slice acceptance

1. Adaptive intake and initial human choices have separate exact owner outcomes;
   approved classes support in-bounds routine work without new human decisions
   solely for owner operations. The complete selected local-advisory route requires
   no authenticator acquisition from Charter setup through Contracts lifecycle,
   evidence-source admission/revalidation, restart and fresh repeat/correction.
   Retained credential routes remain honestly labeled. Recommendations never activate.
2. Complete owner-established C/dependencies retain immutable permitted use;
   the local lifecycle/authority selection must actually be supported by compatible
   versioned owner rules. Until it exists, current credential/review rules still
   refuse unsupported use; they are not permanent requirements of the selected
   workflow. Preserve actual selected review, with no fabricated four-actor
   assurance or author-as-independent-reviewer substitution. Independently justified
   requirements and complete populations remain unchanged by a favorable result.
3. Each actually required definition/use has positive owner-resolved applicability.
   Use `resolve_project_admission_scope_v3` from the outset. A durable v3 footprint,
   including a closed positive NotCommitted attempt leaving D current, never
   permits v2-reader fallback. Original D request replay is history only. Current
   G succeeds only with actual positive non-applicability or satisfied required
   qualification; unsupported qualification refuses its dependent use. Required
   unresolved Q refuses Q-dependent use without inventing every hypothetical scope.
4. Bind the exact captured instance/schema closure to the subject and case.
   Observe the actual retained request input source
   `request_ref#input/role`, whose revision is the complete inline input-content
   fingerprint, under its native authoritative source contract. Do not echo the
   expected revision or claim latest-workspace conformance. A stronger current-
   workspace question requires supported new capture/binding.
5. Contracts-domain Coordination closes complete direct requirements, plan,
   admitted capability and operating ceiling, Purpose/occurrence, independently
   issued Engine authorization, readiness/disposition and immutable attempt basis.
   Valid limited/unknown decision-seeking readiness is held; invalid formation
   refuses. A manifest or dimensional envelope alone supplies none of these.
6. The real validator executes only its exact supported local JSON/dialect closure.
   Unsupported keywords/dialects, remote retrieval, wrong package/fingerprint,
   unavailable restrictions and excessive reach refuse at their actual boundaries.
   No arbitrary executable, hidden network fallback or invented host enforcement.
7. One sealed occurrence frontier accounts for every attempt/refusal/terminal and
   candidate; every in-frontier admission has a terminal result before evidence-
   set and final context close. Missing/late/conflicting/favorable-only selection
   cannot form usable truth. Valid conformant and nonconformant observations both
   reach exact Contracts truth; invalid integrity is a refusal, not repackaged
   baseline blocked-integrity truth.
8. Required currentness is enforced at formation, launch, source admission/commit
   and final closure. Stale D or authority refuses affected use and uses supported
   re-preparation. No substituting G into frozen D, rebinding an old basis, copying
   evidence across occurrences or calling Setup/registry/Context Resolution under
   governance locks. Compose owner checkpoints; no universal atomic journey lock.
9. Historical delivery retains/resolves original definitions, source/intent,
   applicability/D, authorization validity, semantic times, observations and
   closed accounting. Pure current recomputation and immutable evidence-append
   replay alone are insufficient. Fresh equal-content runs get new owner occurrence
   identities; correction gets a new exact snapshot and any required revisions.
10. Summaries distinguish exact conformance findings, intrinsic validity, permitted
    use/direct intent and original applicability/qualification, with “shipment or
    completion obligation: not assessed.” Later G changes no historical truth.
    Pass supplies no replacement, present reliance, parent/work closure or action
    authority. Uncertainty remains uncertainty and uses original owner recovery.
11. Out-of-bounds requests refuse; a permitted resolution uses prior terms and
    native validation of the exact decision. Project-agent resolution and conditional
    human escalation are supported through the bounded caller interface; automatic
    Substrate routing remains explicitly unproven/deferred.
