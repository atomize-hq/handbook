## Outcome, example and human checkpoint

An ordinary typed Rust SDK consumer completes the question: **Does this exact
captured JSON payload conform to this exact supported offline Draft 2020-12 schema
closure through `handbook.dock.json-schema@1.0.0`?** Contracts-domain Coordination
forms complete direct requirements, exact Plan/Purpose and owner occurrence,
readiness/disposition and attempt basis; Engine independently issues and verifies
purpose-bound local authorization. Native Dock executes the real validator.
Contracts admits evidence, closes the finite collection/accounting population,
evidence set and final context, then publishes explained immutable truth that can
be retrieved after process restart.

For illustration, supplied schema S requires `order_id` to be a string and
`quantity` an integer at least 1. An independently justified, reviewed eligible C
and complete dependencies precede observation. Captured
`{"order_id":"A17","quantity":2}` yields a completed conformant observation,
one satisfied claim and `pass`. A separately formed occurrence capturing
`{"order_id":"A17","quantity":0}` yields a completed nonconformant observation,
one unsatisfied claim and `fail`, retaining the actual violation locations/reasons.
Both results explain original `direct_contract` source, `decision_seeking` intent,
permitted use, D or qualified G applicability and **“shipment or completion
obligation: not assessed.”** This example supplies no real schema, actor, path,
freshness value, retention choice or project criterion.

Revoked/stale/wrong-purpose authority or a missing/mixed evidence closure refuses
the affected formation/use and publishes no claim/gate truth. Unsupported dialect,
remote reference, wrong package or unavailable required restriction refuses at its
actual operational boundary. Nonconformance is a valid unfavorable semantic answer;
authority and integrity failures are not that answer.

Implement only after the human approves this bounded plan and all hard predecessors
are proven complete. Stop after Packet-3 implementation, proportionate verification,
causal review and local commit for the human's result recap. This independently
useful first complete check is its own checkpoint. Packet 4 remains its existing
broad repeat/correction/resolution outcome; no successor implementation or detailed
Packet-4 planning is delegated here.
