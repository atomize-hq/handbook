## Task-boundary choices

| Choice | Useful property | Cost or confounding issue |
| --- | --- | --- |
| Exact-final platform gate, then navigation, then packing | Each implementation begins with a qualified baseline and ordinary edit costs are repaired first | Packing evidence waits for a separate layout change; that layout itself needs qualified native delta tests |
| Exact-final platform gate, then packing with navigation frozen; navigation as a separate task | Directly isolates file layout and codec effects on the reclaimed history | Whole-publication speed remains subject to the known collection scan; claims must remain scoped |
| One task with independently pinned, sequential gates | A single coordinator can preserve state and execute the sequence | Prior fixed deadlines already left late platform checks unperformed; a large brief can repeat that failure |
| One broad combined optimization | Could produce a better final system in one checkout | Changes navigation, physical placement and codecs together; weak causal measurements and larger recovery surface |

Platform research or implementation may be independent work, but destructive tests must wait for a known-correct baseline and completed preservation checks. Separate concurrent mutation of the same history root is not an option.

## Required equivalence and fault questions

- Enumerate and hash the exact logical record set before and after conversion independently of the new resolver. Check original accepted outcomes, current/retained content, retired-content refusal, absent requests, durable cancellation, same intent and different intent.
- Exercise a completely written but unselected candidate and orphan pack; neither completeness nor discoverability grants commitment.
- Interrupt pack creation, sealing, index installation, catalog publication, loose-file removal and later repacking/old-pack removal. A successful return must have a defined recovery meaning; a late uncertain return must resolve the original operation rather than replay it blindly.
- Hold snapshot/read leases, prepare a candidate, publish a successor, take a quiescent backup and restore to a new root across relevant pack lifetimes. Use native Windows handles without delete sharing for the appropriate refusal/deferred-deletion checks.
- Define strict behavior for bad offsets/lengths/types/checksums, duplicate keys, wrong record digests, missing catalog/index/pack and decompression bounds. Do not silently treat corruption as absence or let fallback repair it by accident.
- Verify no original record identities or authored bytes change as a side effect of compaction. Preserve old selected history, exact replies and the content-retirement policy.

## Bounded workload shape

Use tiny A/B stores for protocol/fault tests on the required native platforms. Use H1k/H10k smaller fixtures for boundary and geometry cases. Reuse the already durable H101k dataset for the primary long-history comparison on one host; avoid another full durable history per cell and per host. Actual source lineage, synthetic subsets, copied fixtures and newly generated histories must be labeled distinctly.

Packing lookup and maintenance can use the fixed small document corpus to isolate history length. A separate navigation tier can vary collection size and changed-document/relationship counts. B materialization remains a complete-generation workload. Full audits remain separate from normal point lookup.

Report file count by family; logical lengths; calibrated allocated-file bytes; peak temporary space; startup and steady-state RSS; physical bytes read/decompressed per logical record; container/index opens; early/middle/recent/missing/lost-reply resolution; publication versus maintenance time; and backup/restore cost. New processes alone do not establish device-cold reads. Unsupported cache eviction, physical allocation or physical-write measurement must be labeled, not approximated under a stronger name.

The previous 32 GiB combined owned-logical-byte and five-million-file ceilings are reference constraints. A fresh inventory must include preserved originals, the operational archive, restored clones, build/evidence artifacts and overlapping loose/packed data before admitting another large stage. Finite per-stage time/RSS limits and stop criteria remain to be finalized with Pro's recommendation.
