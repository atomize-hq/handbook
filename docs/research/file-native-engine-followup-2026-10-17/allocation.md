Execution qualification: the eight-worker/currently-eligible cohort bound is not
an enforced quota on every retained sealed candidate. The speculative 2/4/8 waves
leave 1+3+7 = 11 rejected stale candidates in each store. Four older stale
candidates plus the eight new candidates imply 12 unselected sealed artifacts at
the final preparation barrier. They remain protected and counted in the combined
allocation; stale artifact bytes are reported separately from currently eligible
pending bytes. The original eight-candidate wording must not be read as a tested
strict bound on all retained candidate artifacts. Such an engine quota remains
unimplemented; the 4 GiB pending-byte and 48 GiB combined allocation budgets are
separate bounds.

The contention controller allows three pure retries **after** the initial attempt
(four attempts maximum), rather than three attempts total. The planned 60 s
small-request aggregate budget is an observation check, not a separately enforced
controller deadline; raw per-request endpoints retain the actual duration. Native
lock-wait limits and process/case ceilings remain enforced. Contiguous 1/8/64
changed-ID batches start at `d000000`; the word sparse above refers to their
fraction of the large collection, not a scattered-key update distribution.

Post-cap A continuation runs only after the measured scheduler and only from
positive selected authority. It keeps the original censored initialization,
uses a separate 900 s view-resume cap and 900 s missing-publication caps, and
measures a conservative additional-file reserve before launch. That reserve

use the native file-byte convention above; source sizes are bounded to 128 KiB
including the fixture's 64 KiB attachments and admitted suffixes. The combined
48 GiB allocation and 160 GiB free-space guards remain unchanged.
Native peak memory is Windows peak working set and Linux maximum RSS, recorded
separately with the platform; they are not identical cross-platform measures.
