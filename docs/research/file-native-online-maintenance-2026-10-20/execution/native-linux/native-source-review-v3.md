## F2: exact stdin delivery

Driver now records input_bytes_expected, input_bytes_sent, stdin_closed,
input_fully_delivered, input_broken_pipe, exact wire SHA and written-prefix SHA.
Only successful os.write counts bytes. BrokenPipe closes that pipe without
advancing the offset. Full means every encoded byte was actually written and
the owner closed stdin; it does NOT infer that a child consumed those bytes.
Already-produced stdout is drained before more stdin; stdout before complete
delivery is a violation. Normal success AND semantic exit2 require complete
delivery. Explicit registered termination/expected86 may retain incomplete
input as a labelled control, never successful input validation. Callback-before-
stdin failures remain failures with zero delivered bytes. Overlap proof now
requires input_fully_delivered rather than the old any-byte flag.

canonical INPUT length twice (start/final), up to four env copies, worst-case raw
escaping and128KiB metadata, bounded above by parent profile event_bytes. It does
