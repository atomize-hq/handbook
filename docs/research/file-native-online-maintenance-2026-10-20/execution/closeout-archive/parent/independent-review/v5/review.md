## R1 [P1] Close all mapped roles back to allowed accepted authority

Primary file: `physical_decoder_v5.py:266-274,324-393,597-629`; imports/adapters: `outcome_oracle.py:verify`, prior `verify_operational.verify` and navigation `oracle.verify`.

`verify_packs()` authenticates every pack and every mapped occurrence, but returns typed raw inventory without checking semantic ownership. `discovery_proof()` checks the forward direction: each required role of each processed accepted publication has a mapping, explicit deferred hole or terminal exclusion. It never checks the reverse direction: every selected mapped key must belong to the accepted/allowed cohort. `verify(...,inventory=None)` deliberately permits no external inventory; in that normal API mode the optional equality check at603-604 supplies no reverse closure. The semantic, navigation and request-intent adapters walk accepted selected history and referenced content, so they do not visit an unrelated extra packed key.

Concrete static counterexample, not a runtime result: preserve a valid accepted store and add a completely unselected attempt's `attempts/unselected/candidate.json` to a well-formed pack/index descriptor. Keep all counts/ranges/tree hashes, pack/index hashes, catalog binding and selected Work packs consistent. Use an available segment/range slot and stay within limits. The extra body can be valid JSON and hash-correct. All accepted outcomes/content remain unchanged; forward coverage still passes; `verify_packs()` includes the extra record; no subsequent assertion rejects its unaccepted owner. Equivalent extra publication, result, hint or allocation entries are not generally examined unless they happen to be requested by accepted history. The physical bytes must not become proof that their record was eligible or accepted.

This is a completeness defect in the independent qualification oracle, not evidence that the engine currently emits unaccepted records or that normal semantic lookup would accept them. It matters because this checker is intended to catch exactly such construction/cohort regressions under the hard semantic-authority gate.

Required fix: derive a permitted-role/owner relation from authenticated `SELECTED` predecessor history, then validate **every selected mapped key and its exact role binding** before reporting the full representation as passed. Cover all five typed roles:

- publication: exact accepted selector identity, body/id/store/sequence binding;

- candidate: accepted attempt with its existing store/request/intent/predecessor/purpose constraints, preserving legitimate retained/retired representation policy;

Do not accidentally prohibit legitimate prior-format accepted-attempt retry allocations merely because their allocation filename is not a selected publication id. If an older format admitted such evidence, document and verify its narrower accepted-owner rule rather than accepting arbitrary attempts. Likewise, physical retention of already mapped retired metadata is legal and must not resurrect content. Whole-descriptor writer dedup is not another accepted publication and must not inflate accepted count.

Keep candidate/pending-output context explicit. `Decoder.candidate(...,authority=self)` already carries the captured selected decoder: validate candidate mapping against that authenticated accepted authority, not against the candidate catalog or journal as a new semantic authority.
