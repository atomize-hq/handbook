Journal `PACKING.json` (:135 packing.rs) has only id/status/expected_config/target catalog/old descriptors and byte counters. `packing-owners/<id>.json` is an initial ownership receipt, not a selected work root. Current abort is allowed only for status building, changes it to aborted-owned, and releases **no** allocation. Resume accepts installed/registered/cleaning/complete with a catalog. Ordinary Store::open does not replay maintenance.

Activation checks current STORE target first. If it already equals target, stale installed journal text can proceed without rollback. If another target is current, only installed + exact expected config may activate. This is the correct selected-authority direction, but does not preserve work through arbitrary successors: a new build archives registered/complete/aborted-owned PACKING at :258-261 and initializes a new `old` list from the current catalog. Archived journals are not replayed/merged by current code. A prior selected-but-not-cleaned generation can lose its pending retirement work; adding a second activation cannot rely on current archives for safe resumption.

Cleanup enumerates all_mapped into memory, verifies each existing loose duplicate against canonical representation, preserves mapped B publication controls, removes others, then checks journal.old against **only the current new catalog**. This was safe under the full reader drain but cannot be reused with per-generation pins. It does not inspect older generations, builders, successor work roots or persistent physical owners. Deleted counters are saved only at batch end; a crash after removal but before save loses that recorded credit. Present/absent reconciliation is required; a stale counter is not proof of reclaimed bytes.

`install` (:186) names files `packs/<content_hash>.pack|idx` and uses io::install_original (:158 io.rs). ## 8. Concrete minimal protocol proposal

The names/constants below are proposed private implementation choices, not existing format facts. Start with one maintainer M; no daemon, scheduler or general locator database.

### 8.1 Explicit version and initial legacy quiescence

Use a new supported **STORE version 3** for generation-aware storage (new code keeps legacy v1/v2 reading). The existing binary rejects version 3 in packing::catalog before an ordinary Store::open returns. Do not leave STORE version 2 and merely assume old binaries adopt new pins.

For the first v1/v2 -> v3 conversion, fully prepare/verify outside exclusion. New code reading a legacy store continues to hold the existing `pack-readers.lock` shared just like old code. Conversion releases its own old lease, acquires the existing `pack-readers.lock` exclusive to drain every cooperating old operation, then **tries W**, releasing/retrying outside exclusion if busy. With M and W acquired and legacy readers drained, CAS exact legacy STORE bytes and atomically install version 3 plus a unique initial generation binding. Release W and legacy exclusion promptly. This one-time conversion waits for valid old operations; it never revokes them. A lost process releases native handles, not persistent preparations. Persisted old candidates/packets remain owned and are later read through current new-code physical state.

All successive v3 readers/activations use a separate short `physical-capture.lock` Q and unique generation pins. New captures after v3 must not require the legacy shared lock. Old binaries obtaining the legacy lock after conversion then read v3 and refuse before eligible I/O/mutation. An old operation that had already opened the legacy store was included in the exclusive drain; fresh nested Metrics are covered by that outer operation, and direct library selection must capture/reject before publication/result reads. Init on an existing root refuses. Custom external library clients bypassing these funnels are not certified. Ordinary B shell consumers continue via preserved loose controls.

Crash boundaries: before STORE replacement legacy remains selected; after replacement old clients refuse, even if a new-mode journal is stale. A process crash must not require an always-running legacy-fence owner. Test old binary already holding a lease, old prepared candidate selecting after conversion, old binary first open after conversion, process death during conversion, and new binary reading/restoring an unconverted image. This is an initial compatibility boundary, not a relaxation of online successor activation with long-lived v3 readers.

### 8.2 Reader capture

The selected physical binding is bounded and names store identity, protocol/version, monotonic ordinal plus never-reused generation id, catalog hash, and maintenance-work root identity. Keep selection in the same atomic STORE replacement; do not introduce two independently selected authorities. An ordinal by itself is not a reusable lock pathname.

Acquire Q shared; natively read/strictly validate only the small STORE binding (prospectively <=4 KiB); open the existing unique generation pin file read/write, acquire shared native pin lock, and validate pin identity/binding. Missing/mismatched pin refuses or retries from capture, never creates an old pin on demand. Release Q. Load/hash/validate full catalog and required files/index outside Q while retaining the generation pin. `Metrics` owns that captured handle across all ordinary I/O. Repeated same-root capture returns it; helper metrics either capture independently or explicitly borrow a scoped handle whose parent outlives them. No temporary namespace rebinding.

Capture does not walk old generations, retirement journals, deferred items or the whole index. Reserve the existing 64-KiB startup/routing envelope across **all** binding+catalog/root routing reads, rather than allotting 64 KiB to each. Set a compatible catalog cap within the remaining envelope or explicitly freeze a refusal envelope before evaluation. Do not stat all packs under Q. The legacy whole-index reader still loads the relevant whole index outside Q for checkpoint 1.

An old generation pin covers loose fallback for *every* eligible key, including keys absent from its catalog and keys whose semantic publication occurs after physical capture. Therefore no semantic head recapture is required for physical/semantic coherence. Pause after physical capture, publish/compact, resume semantic capture: cleanup must retain those fallback instances until the old generation drains.

### 8.3 Build and activation

Acquire M nonblocking and durable bounded resource ownership. Capture/pin current physical parent and authenticated semantic cutoff; retain required semantic proof roots durably. Build/verify complete replacement outside Q/W. Inputs are protected by captured pin and the scoped preparation/semantic lifetime rules. A resumed builder must not reopen a sealed generation just to recover a process lease: its durable owner must name retained physical instances and semantic roots, or it abandons/rebuilds safely. No durable owner means no right to reclaim its forecast.

Persist immutable transition plan before selection: exact expected STORE token, new generation/catalog/work-root identities, complete candidate instance set, old generation seal, retained input ownership, cutoff/progress/deferred roots and inherited retirement work. Allocate the new unique pin file and identity before binding selection; no new reader needs to create it. Candidate validation includes all indexes/pages and record identities, descriptor limits and coverage, resource reservation, and semantic eligibility proofs.

Acquire Q exclusive, try W exactly once. If unavailable release Q and retry outside it. Under both do only exact expected physical token/config check, bounded identity/admission facts, and atomic STORE replacement. Do not walk history, membership, generations, deferred queues or journals; do not fully authenticate indexes, stat every container, verify duplicates or delete. Old generation is sealed by the changed selected binding: ordinary capture can obtain only the current id while Q is held. Do not add a second seal file whose crash ordering could contradict STORE. The new binding and immutable transition carry recovery facts. Release W/Q; retain only ordinary new generation/input protection as needed.

Semantic publications after cutoff are legal; physical CAS does not compare SELECTED equality. Proof that cutoff belongs to captured selected ancestry and that candidate data is immutable is established outside exclusion, with roots held. Mutable exclusions require conservative deferred eligibility or retained ownership, not a history-sized activation recheck. Candidate/allocation records whose eligibility may change are held/excluded until ownership is stable. Current publications/retirement controls stay semantically authoritative.

### 8.4 Retirement, physical instances and no reuse

Store new containers under generation/build-instance paths such as `packs/<birth-id>/<hash>.pack|idx`. The descriptor authenticates instance path plus raw/container identities and version. Never reuse a birth-id/path after a retirement claim, even for equal bytes. Reusing an existing live instance across successor catalogs is allowed only before it is claimed and while M owns the reachability decision. Legacy flat paths are read-only legacy instances, never newly re-adopted by v3 builders. An identical new pack gets a different instance path; matching content hash does not authorize adoption of a retiring name.

Keep M through each bounded deletion batch, including individual native remove calls and claim/progress updates. Neither Q nor W is held during deletion. Since selection/build/claim are serialized by M, no contender can adopt a claimed instance mid-delete. The unique-path rule also protects recovery after a maintainer dies mid-native-call. Do not rely on a mutable journal state alone to permit re-adoption.

A loose duplicate can be removed only after (1) selected authenticated replacement/raw identity exists and remains reachable, (2) exclusions and durable owners permit it, (3) **all sealed generations older than the replacement frontier are drained**, including unmapped fallback generations, and (4) the exact immutable loose instance is irreversibly claimed. Permanent accepted paths are never recreated by cooperating publishers; new logical names remain unique. If any path family can actually be recreated, extend the instance/claim protocol to its writer before deleting it online. B publications are excluded forever from this deletion set. New current readers whose catalog can still fall back to a proposed loose target block its deletion; replacement coverage must be preserved through every successor.

For pack/index removal, absence from current catalog is insufficient: no undrained generation, builder durable owner, staging owner or still-required cleanup replacement may reference the instance. Successors inherit pending work and preserve replacement reachability (or substitute verified exact replacement). ### 8.5 Bounded registry and journal retention through 1,000+ activations

Do not append one permanent registry/journal/owner file per activation or walk every predecessor on open. It contains pending retire ranges/items, deferred eligibility and resumable cursors in bounded streaming containers.
